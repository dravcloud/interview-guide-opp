Interview study guide · C# / .NET

Object-Oriented Programming, served as A PIE

Interviewers almost always ask about the four pillars of OOP. Remember one word, "A PIE", and you have all four in the order most people expect.

Interview tip: each pillar below has a ready-to-say answer. Practice saying it out loud in under 30 seconds, then add one example from your own projects.

Sheet 0 · The basics

Class = blueprint. Object = the house you build.

An architect can build many houses from one blueprint. They all share the same structure, but each has its own color, owner and address. That is exactly how a class relates to its objects.

Class
The template. It defines the data and behavior something will have.
Object
A concrete instance created with new.
Field / Property
A piece of data the object holds: Color.
Method
An action the object can perform: Paint().
Constructor
A special method that sets up the object when it is created.
public class House                 // the blueprint
{
    public string Color { get; set; }
    public int Bedrooms { get; set; }

    public House(string color, int bedrooms)  // constructor
    {
        Color = color;
        Bedrooms = bedrooms;
    }

    public void Paint(string newColor) => Color = newColor;
}

var annasHouse = new House("Blue", 3);   // object 1
var luisHouse  = new House("Green", 2);  // object 2

Say it in the interview"A class is a blueprint that defines state and behavior. An object is a runtime instance of that class, with its own values. I write the class once and create as many objects as I need with the new keyword."

Sheets 1–4 · The pillars

Each pillar in five parts: analogy, test, code, pitfall and the answer to say

A

Abstraction

"Show the WHAT, hide the HOW."

Analogy

To drive a car you use the steering wheel and pedals. You don't need to know how fuel injection works.

Quick test

Does the caller need to know internal details to use your class? Then it needs more abstraction.

In C#

interface (pure contract) or abstract class (contract + shared code).

public interface INotifier                 // the WHAT
{
    void Send(string to, string message);
}

public class EmailNotifier : INotifier      // one HOW
{
    public void Send(string to, string message)
        => Console.WriteLine($"Email to {to}: {message}");
}

public class SmsNotifier : INotifier        // another HOW
{
    public void Send(string to, string message)
        => Console.WriteLine($"SMS to {to}: {message}");
}

// The caller only knows the contract
void Notify(INotifier n) => n.Send("anna@mail.com", "Your order has shipped");

Common mistake: huge interfaces with 20 methods. Prefer several small, focused interfaces. That is the Interface Segregation Principle, the "I" in SOLID.

Say it in the interview"Abstraction means exposing only what a consumer needs and hiding implementation details. In C# I do it mainly with interfaces. For example, my services depend on IRepository, so they don't care whether the data comes from SQL Server or an external API. That also makes the code easy to test with mocks."

P

Polymorphism

"One call, many behaviors."

Analogy

The "Play" button exists in Spotify, YouTube and a car radio. Same command, each one does it its own way.

Quick test

Do you have an if or switch checking an object's type? That is usually a job for polymorphism.

In C#

virtual in the parent + override in the child. Interfaces work too.

public class Animal
{
    public virtual string MakeSound() => "...";
}
public class Dog : Animal { public override string MakeSound() => "Woof"; }
public class Cat : Animal { public override string MakeSound() => "Meow"; }

var animals = new List<Animal> { new Dog(), new Cat() };

foreach (var a in animals)
    Console.WriteLine(a.MakeSound());   // Woof, Meow
// The same loop still works if you add a Cow class tomorrow

Common mistake: writing if (a is Dog) ... else if (a is Cat) .... Every new type forces you to edit that block, which breaks the Open/Closed Principle.

Say it in the interview"Polymorphism lets me treat different objects through the same base type or interface, and each one responds with its own behavior. In C# there are two kinds: compile-time, which is method overloading, and runtime, which is overriding with virtual and override. It lets me add new types without changing existing code."

I

Inheritance

"Reuse what is shared, specialize what is different."

Analogy

A child inherits the family name and traits from their parents, and also develops skills of their own.

Quick test

Only use inheritance if you can say "IS A": a Dog is an Animal.

In C#

: to inherit, base to call the parent. Only one base class allowed.

public class Animal
{
    public string Name { get; set; }
    public void Eat() => Console.WriteLine($"{Name} is eating");
}

public class Dog : Animal            // Dog IS AN Animal
{
    public void Bark() => Console.WriteLine("Woof!");
}

var rex = new Dog { Name = "Rex" };
rex.Eat();   // inherited from Animal
rex.Bark();  // Dog's own behavior

Common mistake: inheriting just to reuse code. A Car is not an Engine; a car HAS AN engine. That calls for composition (a field), not inheritance.

Say it in the interview"Inheritance lets a class reuse and extend the behavior of a base class, modeling an IS-A relationship. C# supports single class inheritance, but a class can implement many interfaces. In practice I favor composition over inheritance, because deep hierarchies become rigid and hard to change."

E

Encapsulation

"Hide the data, expose safe actions."

Analogy

An ATM: you can't reach into the cash box. You use buttons that validate every operation.

Quick test

Can outside code put the object into an invalid state? Then it needs encapsulation.

In C#

private fields, public methods, properties with private set.

public class BankAccount
{
    private decimal _balance;               // nobody touches it directly
    public decimal Balance => _balance;     // read-only

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive");
        _balance += amount;
    }

    public bool Withdraw(decimal amount)
    {
        if (amount > _balance) return false;  // protected rule
        _balance -= amount;
        return true;
    }
}

Common mistake: a public field like public decimal Balance;. Any part of the system could write account.Balance = -500.

Say it in the interview"Encapsulation means bundling data with the methods that operate on it and restricting direct access. I keep fields private and expose behavior through methods or properties that enforce business rules, so an object can never end up in an invalid state."

Resource 1 · Interview answers

Questions you will probably hear

Open each one, try answering out loud first, then compare. Keep answers short: definition, one example, one trade-off.

"What are the four pillars of OOP?"

"Abstraction, polymorphism, inheritance and encapsulation. Abstraction hides complexity behind a simple contract. Polymorphism lets different types respond to the same call in their own way. Inheritance lets a class reuse and extend another class. Encapsulation protects an object's data so it can only change through controlled methods."

Tip: name them in A PIE order so you don't freeze.

"What's the difference between an interface and an abstract class?"

"An interface defines a contract, and a class can implement several of them. An abstract class can contain shared implementation and state, constructors and protected members, but a class can only inherit from one. I use an interface when unrelated types share a capability, like ILogger, and an abstract class when related types share real code, like a base Shape class."

Bonus point: since C# 8, interfaces can have default method implementations, but they still can't hold instance state.

"What's the difference between overloading and overriding?"

"Overloading is having several methods with the same name but different parameters in the same class, and it is resolved at compile time. Overriding is when a derived class replaces a virtual or abstract method from its base class, and it is resolved at runtime. Overriding is what enables runtime polymorphism."

"Why favor composition over inheritance?"

"Inheritance creates tight coupling: a change in the base class can break every child, and C# only allows one base class. Composition lets me build behavior from smaller objects and swap them at runtime, for example injecting an IPaymentMethod into a Checkout class. It is more flexible and easier to test."

"How do you apply OOP in your daily work?"

"In my .NET APIs I separate controllers, services and repositories. Services depend on interfaces, which are registered in the dependency injection container, so I can swap implementations and mock them in unit tests. Entities keep their fields private and expose methods that enforce business rules, so invalid data never gets persisted."

Tip: replace this with a real example from one of your projects. Specific beats generic.

"What is the difference between abstraction and encapsulation?"

"Abstraction is about design: deciding what a consumer should see. Encapsulation is about implementation: protecting the internal state so it can only change in valid ways. They work together, but abstraction answers 'what do I expose?' and encapsulation answers 'how do I protect it?'"

Challenge 1 · Encapsulation · 15 min

Create a Product class with Name, Price and Stock. The price can never be negative, and stock can only change through Sell(quantity) and Restock(quantity).

Show solution 
public class Product
{
    public string Name { get; }
    public decimal Price { get; private set; }
    public int Stock { get; private set; }

    public Product(string name, decimal price)
    {
        Name = name;
        ChangePrice(price);
    }

    public void ChangePrice(decimal price)
    {
        if (price < 0) throw new ArgumentException("Invalid price");
        Price = price;
    }

    public bool Sell(int quantity)
    {
        if (quantity <= 0 || quantity > Stock) return false;
        Stock -= quantity;
        return true;
    }

    public void Restock(int quantity)
    {
        if (quantity <= 0) throw new ArgumentException("Invalid quantity");
        Stock += quantity;
    }
}
Challenge 2 · Inheritance + Polymorphism + Abstraction · 20 min

Implement the Sheet 5 diagram: an abstract Shape class with Area(), plus Circle and Rectangle. Print the area of a mixed list of shapes with a single foreach.

Show solution 
public abstract class Shape
{
    protected string Name;
    protected Shape(string name) => Name = name;
    public abstract double Area();
    public override string ToString() => $"{Name}: {Area():F2}";
}

public class Circle : Shape
{
    private readonly double _radius;
    public Circle(double r) : base("Circle") => _radius = r;
    public override double Area() => Math.PI * _radius * _radius;
}

public class Rectangle : Shape
{
    private readonly double _width, _height;
    public Rectangle(double w, double h) : base("Rectangle")
        => (_width, _height) = (w, h);
    public override double Area() => _width * _height;
}

var shapes = new List<Shape> { new Circle(2), new Rectangle(3, 4) };
foreach (var s in shapes) Console.WriteLine(s);
// Circle: 12.57
// Rectangle: 12.00
Challenge 3 · Abstraction with interfaces · 25 min

Design a payment system: an IPaymentMethod interface with Process(decimal amount), and two implementations: CardPayment (3% fee) and BankTransfer (no fee). A Checkout class must work with either one without knowing which.

Show solution 
public interface IPaymentMethod
{
    decimal Process(decimal amount);   // returns the total charged
}

public class CardPayment : IPaymentMethod
{
    private const decimal Fee = 0.03m;
    public decimal Process(decimal amount) => amount * (1 + Fee);
}

public class BankTransfer : IPaymentMethod
{
    public decimal Process(decimal amount) => amount;
}

public class Checkout
{
    private readonly IPaymentMethod _payment;
    public Checkout(IPaymentMethod payment) => _payment = payment;  // dependency injection
    public void Pay(decimal amount)
        => Console.WriteLine($"Total charged: {_payment.Process(amount):C}");
}

new Checkout(new CardPayment()).Pay(100);   // 103.00
new Checkout(new BankTransfer()).Pay(100);  // 100.00
