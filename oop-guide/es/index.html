Programación Orientada a Objetos con el filtro HEPA

Un filtro HEPA atrapa la suciedad del aire. Los cuatro pilares de la POO atrapan el desorden del código. Memoriza la palabra y ya tienes los cuatro conceptos.

En inglés (entrevistas): se usa "A PIE": Abstraction, Polymorphism, Inheritance, Encapsulation. Aprende las dos: HEPA para entender, A PIE para responder en inglés.

Lámina 0 · La base

Clase = plano. Objeto = casa construida.

Con un solo plano un arquitecto construye muchas casas. Todas tienen la misma estructura, pero cada una tiene su propio color, dueño y dirección. Eso es exactamente la relación entre una clase y sus objetos.

Clase
El molde o plano. Define qué datos y comportamientos tendrá algo.
Objeto
Una instancia concreta creada con new.
Atributo
Un dato del objeto (propiedad o campo): Color.
Método
Una acción del objeto: Encender().
Constructor
Método especial que prepara el objeto al crearlo.
public class Casa                // el plano
{
    public string Color { get; set; }
    public int Habitaciones { get; set; }

    public Casa(string color, int hab)  // constructor
    {
        Color = color;
        Habitaciones = hab;
    }

    public void Pintar(string nuevo) => Color = nuevo;
}

var casaAna  = new Casa("Azul", 3);   // objeto 1
var casaLuis = new Casa("Verde", 2);  // objeto 2
Láminas 1–4 · Los pilares

Cada pilar en 4 piezas: analogía, frase, código y error típico

H

Herencia

"Reutiliza lo común, especializa lo distinto."

Analogía

Un hijo hereda el apellido y rasgos de sus padres, y además desarrolla habilidades propias.

Prueba rápida

Usa herencia solo si puedes decir "ES UN": un Perro es un Animal.

En C#

: para heredar, base para llamar al padre. Solo una clase base.

public class Animal
{
    public string Nombre { get; set; }
    public void Comer() => Console.WriteLine($"{Nombre} está comiendo");
}

public class Perro : Animal          // Perro ES UN Animal
{
    public void Ladrar() => Console.WriteLine("¡Guau!");
}

var firulais = new Perro { Nombre = "Firulais" };
firulais.Comer();   // heredado de Animal
firulais.Ladrar();  // propio de Perro

Error típico: heredar solo para reutilizar código. Un Carro no "es un" Motor; un carro "TIENE UN" motor. Ahí se usa composición (un atributo), no herencia.

E

Encapsulamiento

"Oculta los datos, expone acciones seguras."

Analogía

Un cajero automático: no metes la mano al dinero, usas botones que validan cada operación.

Prueba rápida

¿Alguien de afuera puede dejar el objeto en un estado inválido? Entonces falta encapsular.

En C#

private para datos, public para métodos, propiedades con private set.

public class CuentaBancaria
{
    private decimal _saldo;                 // nadie lo toca directo
    public decimal Saldo => _saldo;         // solo lectura

    public void Depositar(decimal monto)
    {
        if (monto <= 0)
            throw new ArgumentException("El monto debe ser positivo");
        _saldo += monto;
    }

    public bool Retirar(decimal monto)
    {
        if (monto > _saldo) return false;   // regla protegida
        _saldo -= monto;
        return true;
    }
}

Error típico: dejar public decimal Saldo; como campo público. Cualquier parte del sistema podría escribir cuenta.Saldo = -500.

P

Polimorfismo

"Una orden, muchas respuestas."

Analogía

El botón "Play" existe en Spotify, YouTube y un radio. Misma orden, cada uno la ejecuta a su manera.

Prueba rápida

¿Tienes un if o switch preguntando el tipo del objeto? Probablemente debería ser polimorfismo.

En C#

virtual en el padre + override en el hijo. También funciona con interfaces.

public class Animal
{
    public virtual string HacerSonido() => "...";
}
public class Perro : Animal { public override string HacerSonido() => "Guau"; }
public class Gato  : Animal { public override string HacerSonido() => "Miau"; }

var animales = new List<Animal> { new Perro(), new Gato() };

foreach (var a in animales)
    Console.WriteLine(a.HacerSonido());  // Guau, Miau
// El mismo código funciona si mañana agregas una clase Vaca

Error típico: escribir if (a is Perro) ... else if (a is Gato) .... Cada tipo nuevo te obliga a modificar ese bloque.

A

Abstracción

"Muestra el QUÉ, oculta el CÓMO."

Analogía

Para manejar un carro usas volante y pedales. No necesitas saber cómo funciona la inyección del motor.

Prueba rápida

¿Quien usa tu clase necesita conocer detalles internos para usarla? Entonces falta abstracción.

En C#

interface (contrato puro) o abstract class (contrato + código común).

public interface INotificador          // el QUÉ
{
    void Enviar(string destino, string mensaje);
}

public class EmailNotificador : INotificador   // un CÓMO
{
    public void Enviar(string destino, string mensaje)
        => Console.WriteLine($"Email a {destino}: {mensaje}");
}

public class SmsNotificador : INotificador     // otro CÓMO
{
    public void Enviar(string destino, string mensaje)
        => Console.WriteLine($"SMS a {destino}: {mensaje}");
}

// Quien la usa solo conoce el contrato
void Avisar(INotificador n) => n.Enviar("ana@mail.com", "Tu pedido salió");

Error típico: crear interfaces gigantes con 20 métodos. Mejor varias interfaces pequeñas y enfocadas (principio de segregación de interfaces, la "I" de SOLID).

Lámina 6 · Las confusiones más comunes

Parejas que se confunden en entrevistas

ParejaLa diferencia en una líneaTruco para recordarlo
Abstracción vs EncapsulamientoAbstracción decide qué se muestra (diseño). Encapsulamiento protege cómo está hecho (implementación).Abstracción = menú del restaurante. Encapsulamiento = puerta cerrada de la cocina.
Interface vs Clase abstractaInterface es solo contrato y se pueden implementar varias. Clase abstracta puede traer código común, pero solo heredas una.Interface = "PUEDE hacer" (IVolador). Abstracta = "ES UN tipo de" (Figura).
Overload vs OverrideOverload: mismo nombre, otros parámetros, en la misma clase. Override: redefinir el método del padre.Overload = cargar más versiones. Override = pasar por encima del padre.
Herencia vs ComposiciónHerencia es una relación "ES UN". Composición es "TIENE UN".Prefiere composición cuando dudes. Es más flexible.
Clase vs ObjetoLa clase se escribe una vez. Los objetos se crean muchas veces en ejecución.Plano vs casa.

Reto 1 · Encapsulamiento · 15 min

Crea una clase Producto con Nombre, Precio y Stock. El precio nunca puede ser negativo y el stock solo cambia con los métodos Vender(cantidad) y Reponer(cantidad).

Ver solución 
public class Producto
{
    public string Nombre { get; }
    public decimal Precio { get; private set; }
    public int Stock { get; private set; }

    public Producto(string nombre, decimal precio)
    {
        Nombre = nombre;
        CambiarPrecio(precio);
    }

    public void CambiarPrecio(decimal precio)
    {
        if (precio < 0) throw new ArgumentException("Precio inválido");
        Precio = precio;
    }

    public bool Vender(int cantidad)
    {
        if (cantidad <= 0 || cantidad > Stock) return false;
        Stock -= cantidad;
        return true;
    }

    public void Reponer(int cantidad)
    {
        if (cantidad <= 0) throw new ArgumentException("Cantidad inválida");
        Stock += cantidad;
    }
}
Reto 2 · Herencia + Polimorfismo + Abstracción · 20 min

Implementa el diagrama de la lámina 5: una clase abstracta Figura con Area(), y las clases Circulo y Rectangulo. Imprime el área de una lista mixta de figuras con un solo foreach.

Ver solución 
public abstract class Figura
{
    protected string Nombre;
    protected Figura(string nombre) => Nombre = nombre;
    public abstract double Area();
    public override string ToString() => $"{Nombre}: {Area():F2}";
}

public class Circulo : Figura
{
    private readonly double _radio;
    public Circulo(double r) : base("Círculo") => _radio = r;
    public override double Area() => Math.PI * _radio * _radio;
}

public class Rectangulo : Figura
{
    private readonly double _base, _alto;
    public Rectangulo(double b, double a) : base("Rectángulo")
        => (_base, _alto) = (b, a);
    public override double Area() => _base * _alto;
}

var figuras = new List<Figura> { new Circulo(2), new Rectangulo(3, 4) };
foreach (var f in figuras) Console.WriteLine(f);
// Círculo: 12.57
// Rectángulo: 12.00
Reto 3 · Abstracción con interfaces · 25 min

Diseña un sistema de pagos: interfaz IMetodoPago con Procesar(decimal monto) y dos implementaciones, PagoTarjeta (cobra 3% de comisión) y PagoTransferencia (sin comisión). Una clase Checkout debe funcionar con cualquiera sin saber cuál es.

Ver solución 
public interface IMetodoPago
{
    decimal Procesar(decimal monto);   // devuelve el total cobrado
}

public class PagoTarjeta : IMetodoPago
{
    private const decimal Comision = 0.03m;
    public decimal Procesar(decimal monto) => monto * (1 + Comision);
}

public class PagoTransferencia : IMetodoPago
{
    public decimal Procesar(decimal monto) => monto;
}

public class Checkout
{
    private readonly IMetodoPago _pago;
    public Checkout(IMetodoPago pago) => _pago = pago;   // inyección de dependencias
    public void Pagar(decimal monto)
        => Console.WriteLine($"Total cobrado: {_pago.Procesar(monto):C}");
}

new Checkout(new PagoTarjeta()).Pagar(100);        // 103.00
new Checkout(new PagoTransferencia()).Pagar(100);  // 100.00
